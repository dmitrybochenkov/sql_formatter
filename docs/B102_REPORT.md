# B10.2 — интеграция процедур Teradata

База: `785e696ef325154c91cbbaa0251f2f95a82307d4`, 321 тест.
Ветка `feature/b10-stored-procedures`; merge/push не выполняются.

## B10.2a

- Единый `formatter_dialect.select_config` для runtime и CP01–CP05. Положительный
  выбор процедуры выполняется по lexer-токенам; литералы/комментарии не являются
  заголовками. Обычный SQL сохраняет штатный Teradata-диалект.
- Копия грамматики B10.1 получает проектный FluffConfig. Ни реестр диалектов,
  ни установленная SQLFluff не изменяются; карта смещений B6 сохранена.
- INSERT SELECT подключён к существующему узкому AST layout; граница INSERT/SELECT
  теперь явная. DELETE использует тот же безопасный обработчик WHERE, включая литералы.
- Исправлены воспроизводящие тесты B10.1: теперь они требуют идемпотентности INSERT
  и отсутствия E002 у DELETE, а не фиксируют известный дефект.
- На границе коммита a layout процедур намеренно ещё закрыт; DBeaver возвращает
  исходные байты. В b этот временный барьер заменяется транзакцией процедуры.

Целевые проверки: 20 tests / 0 FAIL / 0 ERROR. Полный предварительный прогон:
324 tests / 0 FAIL / 0 ERROR. После старта полного прогона в целевом наборе дополнительно
устранён конфликт двух whitespace-edits на границе многострочного INSERT/SELECT;
20 целевых тестов повторно прошли. Окончательный полный прогон после интеграции
проверит эту версию вместе с процедурами.

## B10.2b

- `formatter_procedure.py`: отдельный AST layout заголовка/параметров, BEGIN,
  DECLARE, SET, CALL, WHILE и вложенных блоков. Никакого regex-разбиения процедур.
- Вложенные INSERT/DELETE вызывают тот же существующий движок; его результат
  переносится узкими diff-edits и проверяется planner с protected spans. Комментарии
  и литералы не заменяются целиком. Все layout-edits имеют одну группу procedure.
- До layout выполняется B6-нормализация только вне protected spans; затем CP01–CP05
  и строгая валидация всего результата. Любой отказ возвращает весь исходник.
- В validator добавлены процедурные AST-контексты: оператор нельзя переместить в
  другой блок/цикл, удалить или изменить; допустимые case/prefix правила прежние.
- Новые golden/assertions проверяют точное оформление простой процедуры,
  вложенность DML, комментарии, многострочные protected значения и второй проход.
- 31 целевой тест прошёл, 0 FAIL / 0 ERROR. Полная транспортная проверка, BOM в
  CLI/адаптере и окончательный полный прогон выполняются в B10.2c.
