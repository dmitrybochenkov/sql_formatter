# B10.3b — внешний отступ процедурного DML

Ветка `feature/b10-stored-procedures`. B10.3a предварительно отделён от начатого исправления и сохранён коммитом `83cc0d7`. Настоящий этап продолжает этот коммит.

## Исправление

В `formatter_modules/formatter_procedure.py` добавлена `local_dml_fragment(source, node)`. Она получает границу DML из AST и определяет внешний отступ по пробелам перед началом этого оператора на его исходной строке. Если оператор записан после другого кода на той же строке, самостоятельного внешнего отступа нет.

Перед передачей DML существующему форматтеру из продолжений удаляется только этот внешний отступ. Внутренние строки protected spans не затрагиваются; относительная разница отступов сохраняется. Для пустых строк учитывается наличие внешнего отступа без требования, чтобы он уже присутствовал. Если непустое продолжение не содержит полного доказуемого внешнего отступа, применяется прежний консервативный отказ всей процедуры.

После обычного DML-форматирования существующая `indented_fragment()` добавляет целевой отступ процедурного AST-блока ровно один раз. Итоговые изменения по-прежнему переносятся в исходник через существующий diff, protected-span проверки и атомарный planner. Безусловных lstrip/dedent нет. Грамматика, CP01–CP05, валидатор, runtime и повторная проверка не менялись.

## Обезличенный пример

Вход:

```sql
CREATE PROCEDURE p() BEGIN INSERT INTO t SELECT a FROM u WHERE a IN (1,
2); END;
```

Результат:

```sql
CREATE PROCEDURE p()
BEGIN
    INSERT INTO t
    SELECT
        a
    FROM u

    WHERE a IN (1,
    2)
    ;
END;
```

До исправления первый внутренний кандидат имел четыре пробела перед `2)`, второй — восемь; публичный вызов возвращал весь исходник с E003. После исправления первый, второй и третий публичные результаты совпадают. Входные относительные отступы 2 и 6 пробелов внутри списка становятся 6 и 10 на уровне процедуры, а не увеличиваются при каждом вызове.
