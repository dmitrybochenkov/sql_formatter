# Teradata SQL Formatter — известные ограничения и roadmap

**Статус:** v1.0 — рабочая локальная версия для `SELECT`, подключена к DBeaver. Git не используется; перед изменениями сохраняем резервную копию.

## Известные проблемы и риски

| Приоритет | Область | Что проверить / исправить |
|---|---|---|
| P1 | Комментарии в `GROUP BY` / `ORDER BY` | `strip()` и `" ".join()` в обработчике могут изменить содержимое сложных выражений или привязку комментариев. Перейти на позиционные правки по AST. |
| P1 | Пробельные строки | Регулярное выражение очистки может затронуть строки из пробелов внутри многострочных SQL-литералов. Сделать очистку с учётом токенов. |
| P2 | Проверка `WHERE 1=1` | Нормализация токенов для сравнения исходного и итогового SQL потенциально скрывает нежелательные изменения. Усилить проверку. |
| P2 | Комментарии в `SELECT` | Обработчик переносит запятые, но не гарантирует единообразные отступы во всех случаях. |
| P2 | Пересечение AST-правок | Пересекающиеся изменения сейчас молча пропускаются; возможно неполное форматирование вложенных запросов. |
| P3 | Предпросмотр DBeaver | Встроенный пример содержит несколько SQL-операторов, включая `UPDATE`/`DELETE`; пока вне области поддержки. Форматирование реальных `SELECT` работает. |

## Roadmap

1. **Надёжность (первым делом).** Исправить два риска P1; добавить регрессионные тесты на комментарии, многострочные литералы, точный ожидаемый вывод и идемпотентность.
2. **Проверки корректности.** Усилить валидацию `WHERE 1=1`; выявлять/тестировать конфликты позиционных правок; доработать `SELECT` с комментариями.
3. **Правило `FROM`.** Одна таблица — на строке с `FROM`; несколько — отдельными строками с ведущими запятыми.
4. **Сложные комментарии.** `/* ... */`, комментарии между запятой и выражением, после `JOIN`; сохранять текст и связь с выражением.
5. **Сложный Teradata SQL.** Проверить `CASE WHEN`, `QUALIFY`, `OVER (PARTITION BY / ORDER BY)`, `CAST`, `COALESCE`, вложенность 2–3 уровня.
6. **Большие запросы.** Проверить скорость и тайм-аут внешнего форматтера в DBeaver.

**Границы текущей версии:** работаем только с `SELECT`; поддержку `INSERT`, `UPDATE`, `DELETE` пока не планируем. Не отключать `validate_sql_unchanged()` ради прохождения тестов. После каждого изменения: `python -m unittest discover -s tests -v`, проверка двух последовательных форматирований и пробный запуск в DBeaver.
